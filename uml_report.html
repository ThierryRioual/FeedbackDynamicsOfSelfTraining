Design Patterns

Strategy Pluggable Objectives

AlgorithmConfig composes pluggable LossFunction, Penalty, and SelectionFunction instances. Switching from logistic to hinge loss, or from hard to Lipschitz thresholding, requires zero changes to the algorithm.

Observer Callback Injection

TestEvaluatorCallback is injected into SelfTrainedGradientDescent.callback and called after every gradient step (t = 0 … T). The algorithm knows nothing about what metrics are tracked.

Shared Engine Theoretical–Empirical Parity

Both MacroscopicStateEvolution and TestEvaluatorCallback delegate pseudo-residual computation to the same compute_abstract_pseudo_residual_from() in utils.py, ensuring bit-for-bit mathematical equivalence between theory and simulation.

Frozen Configs Immutable Hyperparameters

DataConfig and AlgorithmConfig are frozen=True dataclasses, making them hashable and thread-safe. Mutation attempts raise FrozenInstanceError at runtime, cleanly separating config from mutable algorithm state.

TYPE_CHECKING Guard Circular Import Resolution

utils.py uses if TYPE_CHECKING: from src.asymptotics import MacroscopicStateEvolution combined with from __future__ import annotations to provide IDE type hints for plot_autograd_dag without creating a circular import at runtime.

Lazy Cache Amortised Preactivations

TestEvaluatorCallback.__call__ uses closure-based lazy getters (get_preactivations_lab(), etc.) backed by a per-call cache dict. Each forward pass is computed at most once per iteration, even when multiple metrics share the same data split.
